Phone-hosted streaming prototype + Quest spatial client · Rootless by design

Phone runs the host. Quest is the VR client.

VRFlex is being built around a phone-hosted architecture: the Android phone captures and encodes its display, while the Quest client receives the stream and sends tracking telemetry back. The goal is a Virtual Desktop-style experience without root, firmware changes, or replacing Horizon OS components.

VRFlex controls and components

Quest stream client

Receives fragmented H.264 video and PCM audio from the phone over the local network and displays the video in the spatial launcher panel.

Phone host

Uses Android MediaProjection permission to capture the phone display, encode H.264, capture supported playback audio, and accept Quest tracking telemetry.

Tracking and arm offsets

The Quest client sends head and controller position/button telemetry. The phone currently receives telemetry only; applying offsets and feeding adjusted poses into a game runtime is still future work.

Rootless by design

No root, bootloader unlocking, firmware flashing, protected partition writes, system APK replacement, or hidden shell commands.

Downloads

Latest Quest package is rebuilt during the website deployment. The phone companion download is refreshed when its build and release workflow succeeds.

Honest capability status

Implemented in the current code: phone-side TCP control host, Android screen capture and H.264 encoding path, playback-audio capture path, Quest UDP video/audio receivers, and Quest-to-phone tracking telemetry transport. The Quest APK build has passed previously; the phone build is being repaired and rebuilt.

Not finished or hardware-verified: true stereoscopic OpenXR rendering, a runtime that executes compatible games on the phone, injecting tracking/buttons into games, applying arm offsets before game input, Quest microphone uplink, finger-pointer selection, loss recovery/jitter buffering, and end-to-end device testing. Current video is a flat 2D phone-display stream. MediaProjection requires user approval. Launching a Quest-only APK from the phone is not made possible by this streaming layer.
